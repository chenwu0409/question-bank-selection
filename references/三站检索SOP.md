### 0.3 已知限制（实测得出，别再重试）

1. **内嵌浏览器（Trae）不可用于登录态抓取**：标签页属上层 IDE 会话，代理会话报 `Browser operation belongs to an inactive execution round`（实测 6 次）；browser_use 子代理报「不支持浏览器子代理隔离」。→ 一律用独立 Chrome。
2. **360 极速浏览器 cookie 读不出**：`WinError 32` 独占锁；esentutl 备份语义 `-1032 JET_errFileAccessDenied`；CreateFileW `err 32`。→ 不要在 360 上花时间。
3. **沙箱内启动的 Chrome 会被回收**（端口 9222 拒绝连接）：必须 `dangerouslyDisableSandbox` + WMI `Invoke-WmiMethod Win32_Process Create` 启动，进程才脱离父 shell 生命周期。
4. **PowerShell 读 .ps1 文件时按 GBK 解码**：脚本内含中文路径（用户名/目录名）会乱码 → 一律把逻辑写进 `.py` 文件执行；需要用 PowerShell 时用**环境变量**或**内联命令**，不要用 `-File` 读含中文的脚本。
5. **`python -c` 内联引号易碎**：一律写 `.py` 文件执行。
6. **菁优网检索参数老结论已纠正**：`GET /ques/search?keyword=` 确实只是栏目页（295KB、题链 0）；但检索不是 `POST /search` + `sKeyword`（那是错的，会 302 回首页），而是 **`GET /search?c=0&s={21物理,19数学,22化学}&qb=<kw>&p=N`**。`qb` 才是关键词字段，`c=0` 才是单题（`c=4` 返回试卷结果）。**匿名即可搜**，只是题号被掩码成全 0。
7. **菁优网免登录取题链 ≠ 列表页**：`/math3/ques/`、`/ques/` 是导航页/404；匿名题链只有两条路——① `GET /search?c=0&qb=` 直接给题干（题号掩码，进不了详情）；② `sitemap*.xml → /sj/<uuid> 试卷页 → /shiti/<uuid>`（每张试卷页约 9 条题链）。登录态下才有真实加密题号，详情走 `/<subject>/ques/detail/<加密id>`（`/shiti/<uuid>` 仅作兜底）。
8. **CDP `Runtime.evaluate` 顶层不接受 `return`**：写 `return 1+1` 报 `SyntaxError: Illegal return statement` → 表达式必须包一层 IIFE `(function(){ return … })()`。
9. **标签页可能整体无响应**：某个标签页的渲染进程卡死后，对它 `Runtime.evaluate` 会**永久超时**（socket timeout 40s），而不是立刻报错。→ 挑标签页时先探测（`cdp_client.pick_tab`），跳过无响应的；别在死页上反复重试。
10. **选标签页不能无条件回退到任意页**：在 `example.com` 上跑「登录态检测」会得到假 FAIL。→ 站点探查必须限定 url 含目标域名的标签页（`fallback_any=False`），没有就新开一个。
11. **验证页判定要看可见文本，不能扫原始 HTML**：出卷网与二一的首页 JS 里常含 `title:"安全验证"` 字样，直接正则扫 HTML 会把正常首页误判成验证页。→ 先剥掉 `<script>`/`<style>` 再匹配。
12. **HTML 实体在写文件时会被解码**：`.py` 里写 `.replace('&', '&')` 会变成空操作。→ 用 `from html import unescape` 处理实体。
13. **单次网络超时不等于站点有滑块**：预检探滑块时一次 `WinError 10060` 就判 FAIL 会造成假警报。→ 3 连发中有效样本 ≥2 才下结论，样本不足时报"网络异常，先重试预检"，不报"有验证"。

**21cnjy「答案 0/10」复核（2026-11-06 二次取证；结论：站点付费墙，不是会话被搞坏）**

- **检索链路没有退化**：同一查询 `?xd=2&chid=6&content=杠杆平衡条件 计算` 今日返回的题号与 11-03 存档一致（`76699165`/`65034777`/`64208417`…），今日重抓 `76925585` 仍解析出完整题干与 5 个小问 → 搜得到、题面读得到，与答案可得性是两件事。
- **不是接入新站后才坏**：11-02/11-03 保存的 48 个详情页，`access` 全部为 `false`、`answer/answer_text/explanation` 全空；早于出卷网/菁优网接入。
- **没有会话污染**：`session_state_20261106.json` 里 21cnjy cookie 数 = **0**（导出只覆盖 chujuan/jyeoo）；三站只共用 Chrome profile 与 9223 端口，cookie 按域隔离，登录别站不会删 21cnjy cookie；三个抓取脚本各自独立 UA、无共享 cookie jar。
- **字段取证**：详情 JSON `"isVip":false`、`"access":false`、`"answer_json":[""]`、`"answer_text":null`、`"explanation":null`；答案与 `access` 同在一个 bootstrap JSON 里，不在独立接口。
- **接口探测**：`/question/answer/<qid>`、`/question/detail/<qid>?answer=1`、`/api/question/detail/<qid>`、`/api/question/answer/<qid>`、`/question/analysis/<qid>`、`?show_answer=1` 均 **HTTP 404** → 没有"另一个答案接口"可绕过。
- **站点政策**：`https://zujuan.21cnjy.com/help/vip` 明确「查看试题答案解析」是付费权益（普通用户按题 2 学币/题、另有 20 题/天额度；VIP 不限）→ 拦截层是「未登录 + 付费权限」，不是接口变更。

### 0.5 跨站去重判据

- **指纹范围**：只取题干文字，抹掉 HTML 标签、站名水印（组卷在线/菁优网/二一组卷网/21世纪教育网/试题篮/本题/来源）和空白。
- **数字归一**：所有数字替换为 `#` 后再取指纹。
- **判定顺序**：同指纹 → `重复`；数字归一后同指纹 → `结构重复`（跨站转载/换数字）；型号要素集合相同（围栏/门/分割/矩形/面积/二次函数/反比例/中点/杠杆/电路/装置/化合价/催化剂/控制变量）→ `结构重复`；数字+关键词重合 ≥0.75 → `疑似`；其余 → `全新`。
- **工具**：`scripts/dedupe.py`，基准文件必须含三站全部已入库题（`items.ndjson`）。
- **落地**：同一题跨站只保留一条主记录，其余记来源副本；`结构重复` 不得直接放行，须上游写 `dedupe_exception` 说明新增覆盖的必测动作。

## 第二章 用户交接协议（关键）

**凡需要用户动手的步骤，必须完整走完 H 流程，禁止让用户操作后系统无声卡住，禁止同一问题反复让用户重做。**

### H 通用五步

1. **系统先备好窗口/页面**：把该点的页面打开到"只差用户点一下"的状态（已启动独立 Chrome、已停在登录页或验证页、已填好关键词）。
2. **明确告诉用户点什么**：给出**窗口标题 + 页面位置 + 具体动作**，一句话可执行。例："Chrome 窗口『出卷网 - 登录页』，点右上角手机号图标 → 输入你注册时用的手机号与验证码 → 回车"。
3. **用户完成后系统自动复验**：不靠"用户说好了"，由系统主动复验登录态/验证状态（出卷网=读页头是否显示手机号；滑块=检测验证页是否消失）。
4. **输出 PASS / FAIL 及原因**：PASS 才继续；FAIL 必须写清失败在哪、还差什么、下一步是什么。
5. **不重复打扰**：同一交接点失败两次即换方案（H3），第三次转为"报告失败并停止"，不纠缠用户。

### H1 登录交接（出卷网/菁优网）

- 触发：P0.2 检测到未登录，或详情页 302 到登录页。
- 步骤：
  1. 用 WMI 启动独立 Chrome（`tmp/launch_chrome.py` 模板，固定 profile `browser_profile`，端口 9222），**必须 `dangerouslyDisableSandbox`**。
  2. 导航到目标站登录页，等待渲染。
  3. 告诉用户：窗口标题（如「出卷网 - 登录页」）、点哪里、账号从哪来（用户自己输入，**系统不代填密码/验证码**）。
  4. 轮询复验：出卷网读页头 `1xx****xxxx` + 「充值中心」；菁优读标题是否已非「用户登录」+ 是否显示用户名。
  5. 输出 `登录态: PASS` 或 `登录态: FAIL（原因）`。
- 注意：登录态存于 `browser_profile`，重启 Chrome 不丢；**不要让用户在 Trae 内嵌浏览器里登录**（系统读不到，见 0.3-1）。

### H2 滑块/验证交接

- 触发：检索或详情返回验证页。
- 步骤：同 H1，页面停在验证页 → 告知用户"窗口『XXX』中间的滑块，拖到最右"→ 复验 → PASS/FAIL。
- 铁律：**不许自研绕路**（不写 JS 模拟、不破解、不换 IP 池）。一次失败即换 H3。

### H3 用户不便配合时的降级

1. 免登录可得的照常做（出卷网检索 JSON / 二一全流程 / 菁优匿名检索列表内联答案）。
2. 需要登录才能拿的部分 → 标注"该站答案非一手/未取得"，并在交付物中如实说明。
3. 任何情况下**不伪造登录态、不绕过付费墙**。

### 3.2 硬性退出规则

1. **任一环节超预算 2 倍 → 立即停下并报告**，写清：已做什么、卡在哪、需要什么决策。继续跑等于重演 31 分钟 OCR 绕路。

## 第五章 P10 结果回写（不写库等于白跑）

题目发出去、学生做完，流程还没结束。必须把结果写回飞书四张表，缺一张都算没完成。

### 5.1 四张表的写入规则

| 表 | 写什么 | 判定与禁止项 |
|---|---|---|
| 作答记录库 | 每题一条：日期、关联题目、关联训练任务、正确与否 | 用户只报对错时，**得分/满分留空，不估算**；备注写「孩子自述对错，家长转述，原始作答未提供」 |
| 错题诊断库 | 做错题各一条：关联题目/作答记录/知识点、错误类型、错因、是否掌握、复测结果 | 没有原始作答 → **错误类型留空**、错因写「待补充：家长未提供原始作答」、是否掌握=false、复测=未测。**不许猜错因** |
| 知识点库 | 掌握程度按 5.2 状态机重判 + 在「掌握状态变更历史」追加一行（日期 + 事实 + 结论） | 单题做对**不升级为已掌握**；只记「关联题做对（单题）」 |
| 训练任务库 | 任务状态、实际完成情况（正确 n/m） | 正确率按实际对错算，与用户口述不一致时**记事实并在备注说明**，不迁就口述 |

写入格式约束（飞书多维表格 API 实测）：链接字段传 `["rec_xxx"]` 字符串数组；URL 字段传 `{"link": ..., "text": ...}`；单选字段传字符串不传数组；日期传毫秒时间戳。

### 5.1a 训练循环（R1 → R2 → R3，必须建真链）

「做题 → 错题 → 补救 → 再错 → 再补」不能只靠 `推荐变式训练` 文本，必须落成关联字段：

| 环节 | 表 | 字段 | 写法 |
|---|---|---|---|
| 轮次 | 训练任务库/题目库 | `训练轮次` | 单选 `R1`（首轮覆盖）/`R2`（错题补救）/`R3`（换题复测） |
| 错题→补救 | 题目库 | `针对错题` | 链接到错题诊断库 record_id（双向，反向字段 `补救题`） |
| 补救→原题 | 题目库 | `来源题目` | 自关联到原题 record_id（反向 `派生题`） |
| 诊断侧 | 错题诊断库 | `补救题` | 与 `针对错题` 是同一对双向字段的另一侧，写任一侧即可 |

写链顺序：R1 任务 → R1 题 → 作答（错）→ 诊断（错因）→ R2 补救题（写 `针对错题`）→ 新作答 → 重判掌握程度；R2 再错开 R3，不原地重复。

字段创建实测（2026-11-04）：
- `type=18` 单向关联：只建字段，不生成反向字段；带 `back_field_name` 会报 `1254089 LinkFieldPropertyError`。
- `type=21` 双向关联：`property={"table_id": ..., "back_field_name": ...}` 可用，自动在目标表生成反向字段。
- 自关联 `type=21` 可建，但**不生成反向字段**（`派生题` 不存在），反向查询用 `来源题目` 筛选。
- 合成链验收后必须删除测试记录，并回读四表计数恢复基线，避免污染统计。


### 5.2 掌握程度状态机（全库唯一口径）

| 状态 | 判定条件 |
|---|---|
| 未掌握 | 首次做错，或从未做过 |
| 部分掌握 | 做过且做对过至少一次（含单题） |
| 已掌握／阶段性完成 | **隔天或隔周换题复测**再做对，同一知识点至少两次独立正确 |
| 退化 | 复测再错 → 退回上一级，并在「掌握状态变更历史」记一行 |

落地要求：每次回写后跑一遍全库重算（证据 = 作答记录库里每个知识点的对错按日期聚合），生成变更清单（原状态 → 新状态 → 依据），再逐条写入。**同日两次做对仍只算一次独立正确**，不升已掌握。

### 5.3 回读核对（必做）

写完必须回读：条数对不对、关联有没有挂上、单选/日期有没有生效。回读不符合就报 FAIL 并给出差异，**不许假定成功**。本次（2026-11-04）实测：作答记录 6 条、错题诊断 2 条、知识点历史 9 条、任务 3 条，回读全部一致。
